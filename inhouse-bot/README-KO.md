## 봇 호스팅

같은 저장소를 연결하고 시작 명령어는 다음과 같이 설정합니다.

```sh
npm --prefix inhouse-bot ci && npm --prefix inhouse-bot start
```

| 이름 | 값 |
| --- | --- |
| DISCORD_BOT_TOKEN | 내전 전용 봇 토큰 |

| ETG_INHOUSE_BRIDGE_SECRET | 새로 생성한 무작위 문자열 32자 이상 |

연결키 생성 예시: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

`DISCORD_CLIENT_SECRET`은 사용하지 않습니다. 기존 홈페이지 Discord 로그인 클라이언트 ID와 시크릿도 변경하지 않습니다.
토큰·연결키는 환경변수로만 입력하고 저장소, 공지, 채팅에 올리지 않습니다. 이미 공개한 값은 재발급합니다.

## 홈페이지

함께 제공되는 최신 홈페이지 전체 업데이트의 `html` 내용을 기존 홈페이지에 덮어씁니다. 기존 `_etg/config.php`와 DB는 유지합니다.
PHP 호스팅에서 다음 환경변수를 설정합니다. 봇 호스팅에만 변수를 넣으면 PHP에는 전달되지 않습니다.

| 이름 | 값 |
| --- | --- |
| ETG_INHOUSE_BOT_TOKEN | 위 봇과 동일한 내전 전용 토큰 |
| ETG_INHOUSE_BRIDGE_SECRET | 위 봇과 동일한 새 연결키 |

닷홈에서 PHP 환경변수를 제공하지 않으면 기존 `_etg/config.php`의 반환 배열에 `inhouse_bot_token`, `inhouse_bridge_secret` 항목을 추가합니다.
이 두 항목만 추가하며 기존 DB·로그인·세션 설정을 교체하지 않습니다. 공개된 `.env` 파일을 html 폴더에 두지 않습니다.

## 기능과 적용 확인

- `/내전`: 모집·진행 중 내전 목록, 참가·예약·취소
- 팀 배정·가위바위보·밴픽·공수 선택·전적은 기존 홈페이지 진행 화면 유지
- 홈페이지에서 내전 대기실·밴픽방·팀 음성방 직접 생성, 참가자 이동
- 내전 공지/밴픽 현황은 직접 전송·수정하며 전용 봇이 15초마다 확인
- 종료 시 전용 봇이 팀 음성방의 참가자와 관전자를 대기실로 이동하고 빈 팀 방 정리
- 기존 공지는 새 봇이 수정할 수 없어 새 공지 성공 후 기존 봇 중계로 예전 공지 삭제 요청. 전환 시 기존 봇도 잠시 실행해 둡니다.
- 기존 서버 도우미 봇의 `/내전`도 남아 있을 수 있으므로 명령어 선택 시 새 내전 봇의 명령어를 선택합니다. 기존 공지의 버튼은 기존 봇이 처리하고 새 공지의 버튼은 새 봇이 처리합니다.

채널 권한 확인 → 홈페이지 파일 업데이트와 비공개 설정 → 새 봇 시작 → 소규모 테스트 내전으로 생성·참가·취소·팀 방 이동·종료를 확인하세요.
로그에 `내전 전용 봇 온라인`이 출력되어야 합니다. HTTP 503은 홈페이지 연결키/토큰/배포 상태를, HTTP 403은 Discord 채널 권한을 확인합니다.
실서버 배포 및 실제 Discord 전송은 코드 제공과 별도로 위 설정이 필요합니다.
